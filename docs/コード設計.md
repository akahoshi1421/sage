# コード設計

これはsageを設計するにあたって必要なコードのルールやライブラリの指定等が書かれています。

## 技術、ライブラリ、フレームワーク

以下を利用します。

### tanstack start

web版で利用します。server側でsqliteの保存や`claude -p`の呼び出しをします。

### Chakra ui

UIライブラリはこちらを利用します。

### storybook

デザインシステムの確認に使います。

### @clack/prompts

`npx @akahoshi1421/sage@latest create`をしたときに使います。

### oxlint/oxfmt

リンター、フォーマッターで利用します。oxfmtはデフォルト設定で良いです。
oxlintは「typescript, vitest, unicorn, react, import, jsx-a11y」のbuild-inプラグインを動かし、jsPlugins機能で「eslint-plugin-storybook」を動かします。

### husky/lint-staged

commit時にリンターとフォーマッター, `tsc --noEmit`を動かします。

### tanstack query

もしAPIとか生やしたいとき使ってください。APIクライアントはfetch APIで良いです。

### drizzle

sqliteの書き込み、読み出しにORMとして使ってください。

### vitest

テストはこれを利用してください。AAAを意識してください。

### jotai

状態管理に使ってください。

### vite+

vitestだのoxlintだとoxfmtだのをまとめられるので可能であれば使って欲しい。tanstack startとの相性が悪ければ使わなくていい。

### その他

なんか他にも入れたいライブラリあれば教えてください。

## デザインシステム

### UI設計方針

ライブラリ依存をできるだけ疎結合にするため、実際のUI部分で`@chakra-ui/react`のimportを禁止します。(oxlintのimportプラグインあたりに特定パスのimportを禁止する方法があったはずです。指定しておいてください。)

ではどうするかというと`components/ui`のようなディレクトリにVStackのようなレイアウトからButtonなどに至るまで独自コンポーネントを生やしてください。基本的には実際のUI部分で極力styled propsを利用しないでください。レイアウトも含めてどうしても(このUIでしかこのスタイルは使えない等)であるときだけ使ってください。これに対しては`components/ui`に関しても似ていて、基本Chakraのtheme(https://chakra-ui.com/docs/theming/overview)でデザインを整えてください。

レイアウトやButtonのUI含め、確認できるようにStorybookに入れてください。

### UIデザイン方針

デジタル庁(https://design.digital.go.jp/dads/)のデザインシステムに準拠します。全て再現しなくて良いので、今回のsageで使うUI郡(ボタン, ダイアログ, アコーディオン等)だけで良いです。また、利用上の注意事項(https://design.digital.go.jp/dads/introduction/notices/)も読んでおいてください。

デジタル庁公式Storybookです。

- HTML: https://design.digital.go.jp/dads/html/?path=/docs/documents-%E3%81%AF%E3%81%98%E3%82%81%E3%81%AB--docs
- React(ただしtailwindで書かれている): https://design.digital.go.jp/dads/react/?path=/docs/documents-%E3%81%AF%E3%81%98%E3%82%81%E3%81%AB--docs

### アイコン

デジタル庁公式のものを使います。`docs/designsystem-assets/icon/svg`です。gitには含めないで。

## テスト方針

目的駆動でお願いします。「この関数がどうか」ではなく「ユーザがこの操作をした結果こうなった」的な観点です。テストのdescriptionもできる限り実装用語も省いてください。

## CI/CD

GitHub ActionsでPRを立てたときにoxlint, tsc --noEmit, vitestを動かし、CIが通ったときにマージができるようになります。

## web版i18n

web上のテキスト等はi18nに対応させます。
英語と日本語で選べます。`npx @akahoshi1421/sage@latest create`の2問目で自由記述の場合は英語になります。
問題用mdはAIがその都度作成するので任意の言語に対応でいいでしょう。採点に関しても同じで任意の言語でいいと思います。

## 開発方針

小タスク1つをcommitしてください、commit時はfix: やadd: のようなprefixをつけてください。英語でお願いしたいかも
ある程度纏ったらPRを投げてください。必要に応じでgit-worktreeで複数エージェントで並列開発して。
