## 設計

Webでできるパターンとローカルでできるパターンの2パターン用意します。ただし、UX的には2パターンというだけで内部的には実質1パターンです。これはのちで詳細に説明します。

## 前提

これはnpmで公開されたパッケージです。不特定多数の人が使います。

`npx @akahoshi1421/sage@latest create`でフレームワークが対話形式インストールされ、展開される仕組みを考えています。

## インストール

対話形式の中身は以下です。

1. claude codeを利用しているかcodexを利用しているか
2. mdやweb版の言語どうするか(選択肢, en, ja, 自由記述)

## 学習環境の構築

ユーザはsageをインストール後、claude codeなりcodexなりを立ち上げ、「/sage-create (任意の技術)」と入力します。そうすると専用SKILLSが呼び出され、エージェントがそのライブラリに対して調べ上げ、問題とヒントと回答が生成されます。

`./questions`というディレクトリが本家同様存在し、そこに

- `warm-up`
- `easy`
- `medium`
- `hard`
- `extreme`

というディレクトリが存在します。エージェントは問題の難易度に応じてどのディレクトリに問題を入れるのかを決めます。

さらにその下のディレクトリは`warm-up/1-hello-world/`のような問題文のタイトルが入ります。`warm-up/{問題番号}-{問題タイトル}`です。問題番号は難易度に限らず一意にしてください。`warm-up`から1から小さい順です。
ただし、無理に`extreme`まで全てのディレクトリを埋める必要はありません。必要に応じて考えてください。学習曲線が小さい技術なら問題文自体少なめで全て埋めなくていいだろうし、学習曲線が大きい技術なら問題文は多めの方が良いはずです。

そしてその下には

- `QUESTION.md` => 問題文
- `HINT.md` => ヒント
- `ANSWER.md` => 答えおよび解説
- `template.{任意の拡張子}` => ユーザが答えを書き込むファイルのテンプレート(たとえばユーザがTSのライブラリに関することを学びたいのならここは.tsになるしRubyなら.rbになる。)
- `answer.{任意の拡張子}` => ユーザが答えを書き込むファイル(初期値は`template.{任意の拡張子}`と同じ)

が生成されます。

## ローカルパターン

`answer.{任意の拡張子}`にユーザが答えを書き込んだのち、`/sage-mark {問題番号}`と入力します。そうするとエージェントがSKILLSを利用して採点を行い、以下の3つのうちどれかを出力します。

- 🟢 正解 (なんかここに一言)
- 🟡 惜しい (なんかここに一言)
- 🔴 不正解 (なんかここに一言)

正解であればsqliteのファイルに正解したと更新してください。

#### 問題文の一覧

### 回答ページ

`参考2.png`を見てください。
左画面は問題文やヒント、答えを見るボタンがあります。
右画面はコードおよびposition: stickyの回答UIです。

また、左画面と右画面はそれぞれ独立スクロールです。

#### 回答ボタン

回答ボタンを押すと`claude -p "/sage-mark {問題番号}"` あるいは`codex exec "/sage-mark {問題番号}"`が実行されます。その後ダイアログが開き、ローカルパターンと同じように「正解」「惜しい」「不正解」と一言を出してください。

「正解」のときは、DialogFooterに閉じると次の問題に進むボタンの2つが出ます。それ以外は「閉じる」だけです。また、ローカルと同じでsqliteの正解更新もして。

#### 答えを見るボタン

ボタンを押すとダイアログが開きます。ダイアログの中身は`ANSWER.md`の中身がそのまま出ます。DialogFooterは閉じるボタンです。

#### ヒントを見るアコーディオン

「ヒントを見る」はアコーディオンのUIになっています。

#### ハンバーガーボタン

`参考3.png`を見てください。開いたらこれが出てきます。「^」はアコーディオンです。問題タイトル(リンクになってる)を見え隠れできます。


#### コード

`answer.ts`の中身をそのまま出します。また。コードを記述し、cmd+Sをすると、保存APIがたたかれ、ローカルの`answer.ts`が更新されます。エディタの内容が保存した内容と違うときは、VS Codeと同じようにファイル名の横に●を出し、cmd+Sで保存できることを暗に示します。

エディタはMonaco Editorで、そのままでは学習対象 (zodなど) の型を知らず補完が効きません。学習対象はいろいろな言語・技術になるので、プロジェクトのルートの`sage.editor.js` (ESモジュール、`sage create`が雛形を作る) をアダプタとして読み込み、Monacoの設定を利用者側に委ねます。`setup` (Monaco読み込み時に1回) と`open` (問題を開くたび) を export し、`project.readFiles` / `project.readFile` でプロジェクト内のファイル (node_modulesの型定義など) を読めます。`/sage-create`がAIエージェントに対象技術向けの中身 (型定義の登録など) を書かせる想定です。言語サーバー (LSP) がある言語では、sageがそれをプロジェクトのルートで起動してWebSocketでエディタに中継し、補完・ホバー・エラー表示・色付け (セマンティックトークン) が言語サーバーのものになります。sageは言語を知らない代わりにLSPを一度きちんと実装し、言語ごとの知識は利用者側 (AI) に置きます。AIの必須作業は「言語と言語サーバーを入れる」だけで、よく使う言語サーバー (pyright、gopls、clangd、rust-analyzerなど) はPATHにあれば宣言不要、PATHに無いコマンドや既定に無い言語だけ`languageServers`に起動コマンドを書きます。sageが知らない拡張子は`languages`に拡張子 → 言語IDを書きます (MoonBitの`.mbt`など)。言語サーバーが無い言語では何もせず素のエディタで動かします (補完や色付けを自作させない)。
